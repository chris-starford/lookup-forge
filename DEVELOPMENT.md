# Developing Lookup Forge

This repository is a Cribl App project: the scaffold generated by Cribl's **Create App** wizard plus the Lookup Forge source. Customer-facing documentation is in [README.md](README.md).

## Repository layout

| Path | What it is |
|---|---|
| `src/lookup-manager/core/` | Engine: types, templates, keys, CSV, mapping and validation, Cribl API calls (`cribl.ts`), sources, Splunk, workers, publishing, diff, scheduling, runner, KV store, usage snippets |
| `src/lookup-manager/ui/` | React UI (self-contained CSS; App-drawn `Select`; help text in `help.ts`) |
| `src/lookup-manager/version.ts` | App version; keep equal to `package.json` and the newest `CHANGELOG.md` entry |
| `src/App.tsx` | Re-exports `LookupManagerApp` as the App root |
| `backend/run-lookups.ts` | Scheduled backend function |
| `config/policies.yml`, `config/proxies.yml`, `config/backend.yml`, `config/schedules.yml` | Cribl declarations |
| `scripts/stage_splunk_lookup.py` | Stages Splunk rows into the Lake staging dataset through HEC |
| `scripts/apply-package-metadata.mjs` | Adds Marketplace tags, scripts and dev dependencies to `package.json` |
| `docs/` | `USER_GUIDE.md` (generated), `RUNBOOK.md`, `splunk.md`, `pipelines/` (staging pipeline), `design/` (Capra spec and build prompt), `workshop/` (example environment guides) |
| `PUBLISHING_CHECKLIST.md` | Marketplace readiness checklist |
| `dev-tests/` | Simulated Cribl API, engine and backend tests, browser test |

The scaffold also creates `openapi.json`, Cribl's full API specification for coding assistants. It is large and generated, and contains example credentials that trip GitHub's secret scanning, so it is in `.gitignore`: keep it locally, don't commit it.

Naming: the App ID and package name are `lookup-forge`; the display name is "Lookup Forge". Internal names keep their original form: the source folder `src/lookup-manager/`, the root component `LookupManagerApp`, the KV and CSS prefix `lm-`, and scheduled-search names `lm_src_*`. They are never shown to users.

Every Cribl API call lives in `src/lookup-manager/core/cribl.ts`. If an endpoint behaves differently, fix it there and keep `config/policies.yml` in step.

## Setup

Requirements: Node.js 22.22.2 or later, a Cribl.Cloud Workspace where you are Workspace Administrator, Chrome/Edge/Firefox.

New clone in an existing Cribl project:

```bash
npm install
node scripts/apply-package-metadata.mjs --repo https://github.com/chris-starford/Cribl-Lookup-Manager --license Apache-2.0 --author "Chris Starford"
npm install            # installs the dev dependencies the script added
npm run dev            # then open Live Preview in Cribl's Create App wizard
```

Starting from a fresh scaffold instead: run the Create App wizard with App ID `lookup-forge` and display name `Lookup Forge`, then copy `src/lookup-manager`, `backend/run-lookups.ts`, `config/*`, `scripts`, `docs`, `dev-tests` and the root Markdown files into it, make `src/App.tsx` re-export `./lookup-manager/ui/LookupManagerApp`, and remove the scaffold's `src/App.css` import.

Notes from building against Cribl.Cloud 4.20:

- UI code must call Cribl through `window.CRIBL_API_URL` (handled in `cribl.ts`); backend code uses relative `/api/v1` paths.
- Use `/m/*/...` for group paths in `policies.yml`; `/m/:gid/...` did not match.
- Live Preview keeps the permission mode the development App was registered with; test Open mode on an installed App.
- Native `<select>` lists can be unreadable inside the App frame; use `ui/Select.tsx`.

## Tests

```bash
npm test          # engine and backend tests (simulated Cribl API)
npm run test:ui   # bundles the UI with the simulated API and drives it in headless Chromium
```

The simulated API (`dev-tests/mock-cribl.ts`) models the KV store, worker groups, lookups, selective commits, deploys, Search jobs, saved searches, collector jobs and external hosts. When a real Cribl API differs from the simulation, update both the code and the simulation.

## Documentation

The in-app guide is the source for `docs/USER_GUIDE.md`. After editing `src/lookup-manager/ui/guide.ts`:

```bash
npx tsx scripts/build-user-guide.ts
```

`npm test` fails if the document is stale or the guide quotes a UI label that no longer exists.

## Releasing

1. Update `APP_VERSION` in `src/lookup-manager/version.ts` and add a `CHANGELOG.md` entry (a test fails if they differ).
2. `npm audit --audit-level=high` must pass.
3. Build and package together, with the same version (packaging alone reuses the last build):

   ```bash
   npm run build && npm run package -- --version X.Y.Z
   ```

4. Test the upgrade from the previous release on a Workspace: **Apps › Installed › Upgrade**, then run diagnostics and one lookup.
5. Tag the release (`git tag vX.Y.Z`) and attach `build/lookup-forge-X.Y.Z.tgz` to the GitHub release.

Versioning: the last number for fixes, the middle number for new features that keep existing lookups working, the first number when existing lookups or settings need migrating. Saved definitions record `savedWithVersion` for future migrations.
